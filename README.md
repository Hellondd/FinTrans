# FinTrans CRM

CRM-система «ФинТранс» представляет собой комплексное решение для автоматизации ключевых бизнес-процессов финансовой компании, специализирующейся на кредитовании, финансовом мониторинге и аналитике. Система разработана с нуля с учетом специфики работы с большими объемами данных (200 000+ клиентов) и обеспечивает полный цикл управления взаимоотношениями с клиентами - от регистрации и верификации до выдачи продуктов, мониторинга транзакций и анализа рисков

## Технологии

- **FastAPI** - веб-фреймворк
- **PostgreSQL** - база данных
- **SQLAlchemy** - ORM
- **Alembic** - миграции
- **Docker** - контейнеризация
- **JWT** - авторизация
- **Recharts** - графики
- **React** - фронтенд

## Требования

- Python 3.11+
- Node.js 18+
- Docker Desktop
- WSL2 (для Windows)

  
## Установка и запуск

### 1. Клонировать репозиторий

```
git clone <repo-url>
cd backend
```


### 2. Создать файл .env
```
cp .env.example .env
```

### 3. Запустить контейнеры (обязательно установить Docker Desktop)
```
docker-compose up -d --build
```

### 4. Применить миграции
```
docker exec -it fintrans-backend alembic upgrade head
```

### 5. Импортировать данные из Excel
```
pip install -r requirements.txt
```
Импорт транзакций идёт дольше из-за ограничения PostgreSQL (32767 параметров), но все данные сохраняются

## Функциональные возможности

### 1. Управление клиентами

- **CRUD операции**: создание, просмотр, редактирование, удаление клиентов
- **Пагинация**: работа с 200 000+ записей без потери производительности (<200 мс на запрос)
- **Поиск**: полнотекстовый поиск по ФИО клиента
- **Фильтрация**: по сегменту (Mass/Premium/VIP/Startup и др.), городу, статусу (ACTIVE/BLOCKED/CLOSED), минимальному доходу
- **Продукты клиента**: просмотр всех финансовых продуктов клиента в модальном окне

### 2. Кредитный скоринг

- **5 факторов расчёта**: ежемесячный доход, просрочки, открытые кредиты, фрод-флаги, активные продукты
- **Автоматический расчёт** при создании или обновлении клиента
- **Определение сегмента**: на основе кредитного скора клиенту автоматически присваивается сегмент
- **Рекомендуемый лимит**: расчёт на основе дохода и кредитного скора

### 3. Антифрод-анализ транзакций

- **6 факторов анализа**: сумма, страна, устройство, время, частота, история фрода
- **3 уровня решения**: `approved` (одобрено), `manual_review` (ручная проверка), `blocked` (заблокировано)
- **Автоматическое создание фрод-алертов** при подозрительных транзакциях
- **API проверки без сохранения**: эндпоинт `/transactions/check` для предварительной проверки

### 4. Аналитический дашборд

- **KPI в реальном времени**: общее количество клиентов, активных клиентов, транзакций, объём сегодня, заблокировано фродом, средний кредитный скор
- **Динамика транзакций**: интерактивные графики (количество и объём) с выбором периода (30/60/90 дней)
- **Распределение по сегментам**: круговая диаграмма с долей каждого сегмента
- **Топ клиентов**: рейтинг по доходу, кредитному скору, активности (медали для топ-3)

### 5. Экспорт отчетов

- **Excel**: выгрузка KPI, топ-клиентов, результатов фильтрации
- **PDF**: сохранение графика транзакций и всего дашборда

### 6. Авторизация и безопасность

- **JWT-токены**: безопасная аутентификация с временем жизни 7 дней
- **Хеширование паролей**: bcrypt (соль 12 раундов)
- **Ролевая модель**: 4 роли с разграничением доступа к API




## Бизнес-логика (Сервисный слой)
В директории `backend/app/services/` реализованы следующие сервисы:
1. **ScoringService (`scoring_service.py`)**: Реализует 5-факторную модель расчета кредитного скоринга и определение лимитов, присваивает клиенту сегмент и уровень риска.
2. **FraudService (`fraud_service.py`)**: Производит 6-факторный анализ транзакций, вычисляет Fraud Score и выносит решение: одобрить, отправить на ручную проверку или заблокировать транзакцию.
3. **ClientService (`client_service.py`)**: Инкапсулирует логику создания и управления клиентами, автоматически рассчитывая их скоринг.
4. **TransactionService (`transaction_service.py`)**: Управляет созданием транзакций, интегрируя обязательную предварительную проверку на мошенничество.

## AuditLog и FraudAlert
Внедрена система автоматического аудита подозрительных транзакций:
1. **Модель и База данных**: Создана таблица `fraud_alerts` (модель `FraudAlert`) для хранения инцидентов со связями к транзакциям и клиентам.
2. **Логирование при фроде**: `TransactionService` автоматически генерирует алерт в базе данных через `FraudAlertRepository`, если транзакция получает статус `blocked` или `manual_review` в результате проверки антифрод-сервисом.
3. **API Управления алертов**: Добавлены защищенные эндпоинты (`/api/v1/fraud/alerts`), доступные только для ролей `admin` и `security` (реализована проверка через `get_current_security_user`):
   - Просмотр списка алертов.
   - Изменение статуса алерта (например, закрытие инцидента - `resolved`).

## Управление продуктами клиентов
Реализован функционал для получения всех финансовых продуктов (кредиты, депозиты, карты) конкретного клиента:
1. **Схема**: Создана схема `ProductRead` для валидации и сериализации ответа API.
2. **Репозиторий**: Добавлен `ProductRepository` для взаимодействия с таблицей `products` в базе данных.
3. **Сервис**: В `ClientService` реализован метод `get_client_products`, который сначала проверяет существование клиента, а затем обращается к `ProductRepository` для получения списка продуктов.
4. **API Эндпоинт**: Добавлен эндпоинт `GET /api/v1/clients/{client_id}/products`, который корректно делегирует бизнес-логику сервисному слою согласно требованиям архитектуры.

## Полезные команды
